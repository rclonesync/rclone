1. Purpose and scope

Rclone is maintained by its individual owner for personal use with rclone and Google Drive OAuth. It authorizes rclone on a device controlled by the user to perform requested file operations. This policy covers that application and this informational website. It assumes no operator-managed backend receives Drive files or OAuth tokens.

2. Authorization and Google Drive permissions

Google handles sign-in and consent. The application does not ask for or store your Google password. OAuth tokens allow rclone to act within the permissions you grant. Access can include file contents and metadata such as names, IDs, sizes, timestamps, and folder structure, depending on the selected scope and operations.

https://www.googleapis.com/auth/drive.readonly

Read file contents and metadata; does not authorize uploads or changes.

https://www.googleapis.com/auth/drive.file

Access to specific files created by or authorized for the app. In ordinary rclone use, this is generally limited to files and folders rclone creates; it is not unrestricted access to existing Drive files.

Other rclone scope options include drive.appfolder (the Google scope drive.appdata) and drive.metadata.readonly. Disclose these or any additional scopes if actually used. Use the least access that supports the intended tasks. A configured root folder is not a substitute for a narrower OAuth scope.

3. How data is used and transferred

Drive data is used only to perform operations you initiate, such as listing, copying, downloading, uploading, or syncing files. Depending on the command and scope, operations may rename or delete data. In the intended setup, rclone communicates with Google’s OAuth and Drive services over HTTPS. Transfers can also involve any other storage destination you explicitly configure.

The application owner does not collect Drive files or tokens through this website, sell personal data, or share Google user data with advertisers, data brokers, or unrelated third parties. Data is not used for advertising, profiling, or AI model training. Necessary communication with Google and any destination you choose is part of carrying out your instructions. If the owner adds a backend, sharing service, telemetry, or another recipient, this policy must be revised to reflect that behavior.

4. Local tokens, storage, and security

In the standard local setup, access and refresh tokens are stored in rclone’s configuration on the device where rclone is configured. Refresh tokens can allow continued access without signing in each time. The default configuration file is not encrypted at rest unless you enable rclone configuration encryption. Protect it using appropriate file permissions, device security, and encryption.

Configuration paths and storage can vary with command options, environment variables, containers, or remote machines. Downloaded files, caches, logs, and backups may retain data on those systems. The owner must inspect these settings and avoid publishing credentials, tokens, configuration files, or sensitive logs. No system can guarantee absolute security.

5. Retention, deletion, and revoking access

Local credentials remain until removed or replaced; their validity also depends on Google’s expiration and revocation rules. Local files, caches, logs, and backups remain according to your device and retention settings. Google Drive files remain until you remove them under Google’s retention rules.

You can revoke authorization in Google Account third-party connections. Remove the rclone remote or token from your configuration and separately delete any unwanted local copies, caches, logs, and backups. Removing local configuration alone does not revoke Google access, and revoking access does not delete transferred files. Contact rclonegdrivesync@gmail.com with privacy questions; never send passwords or tokens.

6. Website hosting and support messages

This static website contains no application analytics, advertising, tracking scripts, cookies, forms, or browser storage. It does not process OAuth callbacks. GitHub Pages, as the hosting provider, may process visitor information such as IP addresses and request logs under the GitHub Privacy Statement. Google processes data under its Privacy Policy. If you email support, the owner and email provider receive the message and any information you include; the owner uses it to respond and retains it only as needed for that purpose.

7. Policy changes and contact

The owner will update this page and its effective date when the app’s practices change. For questions about Rclone, contact rclonegdrivesync@gmail.com.
